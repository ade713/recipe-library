## SQLAlchemy and Alembic Foundations

```md
## 2026-08-17

Built:

- Completed and tested the SQLAlchemy models for the nine core database tables.
- Added source-attribution fields, relationships, foreign keys, required columns, and per-user tag uniqueness.
- Added persistence tests for saving and querying recipes by owner.
- Configured Alembic and generated, applied, reversed, and reapplied the initial PostgreSQL migration.
- Expanded backend CI checks to cover models, migrations, and database configuration.

Learned:

- Pydantic validates API data, SQLAlchemy defines database storage and relationships, and Alembic versions schema changes.
- SQLAlchemy objects move through transient, pending, and persistent states.
- A failed transaction requires `session.rollback()` before the session can be used again.
- Foreign keys enforce referential integrity but do not replace user-ownership checks in queries.
- `Base.metadata` gives Alembic the registered table definitions used during autogeneration.
- `alembic current` reports the database revision, while `alembic check` detects model changes missing from migrations.
- Docker port mappings use `host:container`; PostgreSQL uses host port 5433 to avoid a local port conflict while retaining port 5432 inside the container.
- Autogenerated migrations must be reviewed, linted, and tested in both upgrade and downgrade directions.

Next:

- Build manual recipe CRUD with thin FastAPI routes and user-scoped repository queries.
```
